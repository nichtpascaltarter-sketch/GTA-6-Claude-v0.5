WHAT
- src/world/ntw.h/.cpp: the NTW parser (moved up from step 3, as agreed): records, ids, fields, continuation lines, blocks by a schema predicate, comments, strict value readers. worldc reads world/terrain/terrain.ntw with it. The game doesn't parse text.
- src/world/worldbin.h/.cpp: the world.bin container. Its header has a hash of the whole data, and the table is named sections, each 16-byte aligned. Opening checks the magic, version, table and hash, so a damaged or truncated file is refused.
- tools/worldc.cpp: the world compiler, stage 0 version (a host tool, a small TU of about 5 s). It reads terrain.ntw, checks every layer's grid against its hash and size, and writes build/gen/world.bin and world.rc. world.bin holds 5 sections in 2.67 MB: the terrain record plus the four NTG grids.
- src/world/handworld.h/.cpp:
  - World::gWorldKind (procedural by default) and selectWorldKind() for --world=hand|procedural.
  - embeddedWorldBin(): FindResource/LoadResource/LockResource on RCDATA NT_WORLD. There is no copy: the OS pages it in.
  - loadHandTerrain() decodes the four grids in parallel, fills WorldMap (heights, water levels, regions, coast distance, outlines, channels) and recomputes the splat.
  - loadHandWorld() takes the --worldfile=<path> dev override or the embedded data, and sets up empty roads (with their hash) and buildings (with their cell lists), so every query finds nothing.
- src/world/cellgen.cpp: generateCell returns empty in hand mode. Stage 0 has the terrain only, which the renderer draws from the height map.
- src/main.cpp: the three includes, next to world/interiors.cpp.
- src/game/app.cpp: the three hunks, all behind World::isHandWorld():
  (a) select the world kind from --world before the loader thread;
  (b) the loader's hand branch: loadHandWorld, or FatalError with the reason;
  (c) skip game.init, and stay in the free camera instead of the menu or a new game. --shot and --viewer work as today.
- build.sh: builds tools/worldc when it or its sources are newer, runs it, then windres in build/gen. WORLD_OBJ is set on its own lines, and `$WORLD_OBJ \` is a new line inside the link command; no existing line changed.
