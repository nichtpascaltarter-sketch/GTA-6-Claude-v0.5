The game updates itself, and the hand-built world loads: --world=hand runs the baked terrain from the exe

Automatic updates (src/platform/updater.cpp/.h, update_logic.cpp/.h, src/core/version.h):
- At startup a background thread reads the repository's release list (/releases?per_page=10: drafts skipped,
  pre-releases count, highest version by tag) over WinHTTP with TLS checks on and short timeouts, and downloads a
  newer NeonTide*.exe next to the game. It keeps the download only after checking that it came over https, has the
  size GitHub lists, is an x64 Windows program, and matches its SHA-256 (BCrypt) against GitHub's per-asset digest,
  else a .sha256 / SHA256SUMS asset, else a hash in the release notes. Never an equal or older version.
- The next start checks the pending file again (record, newer version, size, SHA-256, program header), swaps it in
  (the old exe is kept as <exe>.old until the new version has its window), restarts with the same command line and
  continues the same log. "Restart now" in the main menu (U, pad Y or a click) does it at once; when the folder isn't
  writable the menu offers the download page instead. One line in the pause menu; nothing interrupts play.
- Settings > Gameplay > Automatic Updates (default On); --no-update; never in automated runs (--autotest, --shot,
  --benchmark ...). The main menu shows the version (0.02.7-dev between releases; VERSION=0.02.7 ./build.sh or
  set VERSION=0.02.7 before build.bat for a release). README.md and PROGRESS.md describe the release steps.
- Checks (autoupdater agent): tests/updater/update_logic_test.cpp, 196 checks with GitHub's real responses as
  fixtures (-Wall -Wextra -Werror, UBSan); end to end under Wine with real game exes and a local server: download,
  verify, install, relaunch into the new version, and rejections for a wrong checksum, wrong size, a non-program
  file, equal or older versions and an unreachable server; Restart now in the real main menu; the drive smoke's log
  differs only by the version and "no update check (automated run)".

Stage 0 step 2 of the hand-built world (docs/HANDBUILT_WORLD.md). The procedural world stays the default and runs as
before; --world=hand selects the new one, which at this stage is the bare terrain: no roads, buildings or plants yet.

- tools/worldc.cpp: the world compiler. It reads world/terrain/terrain.ntw, checks every grid against its hash and
  size, and writes build/gen/world.bin (2.67 MB, 5 sections) and world.rc. build.sh and build.bat build and run it and
  link the resource into the exe (RCDATA NT_WORLD); in build.sh every output goes through a temp file and a rename,
  and nothing is redone while the resource is newer than worldc and world/, so builds sharing build/ never see a
  half-written file.
- src/world/ntw.cpp/.h: the NTW text parser (records, ids, fields, continuation lines, blocks, comments, strict value
  readers; CRLF and a UTF-8 BOM accepted). Only worldc uses it; the game reads no text.
- src/world/worldbin.cpp/.h: the world.bin container: named, 16-byte aligned sections behind a header whose FNV-1a
  hash covers the table and the data, so a damaged or truncated file is refused.
- src/world/handworld.cpp/.h: --world=hand|procedural, the embedded world.bin (FindResource, no copy), and the loader:
  the four grids decoded in parallel into WorldMap (heights, water, regions, coast distance, outlines, channels), the
  splat recomputed, and empty roads and buildings so every query finds nothing. --worldfile=<path> loads a world.bin
  from disk for development.
- src/game/app.cpp: in hand mode the loader thread loads the hand world, the game isn't initialised and the free camera
  stays up (stage 0 has nothing to play); --shot and --viewer work as before. src/world/cellgen.cpp generates nothing
  in hand mode. src/render/renderer.cpp skips the GPU grass and decor scatter in hand mode (every plant is to be placed
  by hand, decision D2).
- .gitattributes: NTW text keeps LF on every checkout, NTG grids are binary.
- docs/HANDBUILT_WORLD.md v1.1: the AI's details and validator checks (overlapping carriageways, conflicting greens,
  fence crossings), and stair and door geometry for the building kit (4.9) from the animation harness.
