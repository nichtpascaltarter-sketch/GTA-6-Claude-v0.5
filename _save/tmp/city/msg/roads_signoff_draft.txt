What it does:
- src/world/roadsbin.h/.cpp (new): the two sections.
  - "roads", version 1: the nodes (x, y, z, radius, control, highway) and the edges (n0, n1, class, flags, lanes, half width, sidewalk, cut-backs, seed, name, points).
  - "roads.ids": every node's and edge's authored id, in network order, for missions, saves and tools.
  - readRoads rebuilds the node edge lists, the distances, the lengths and the spatial hash.
  - It refuses a section that is missing, truncated, over-long, of another version or inconsistent, gives a reason, and leaves the network empty, never half read.
- tools/worldc.cpp:
  - World, district, roads, signal and transit files go through the world model (loadParsed, compileRoads) into those sections. Errors carry file:line and a code.
  - Blocks, buildings, places and the library stop the build with "no compiler for X files yet", as you decided.
  - The docs say so where they describe worldc's per-kind behaviour: NTW_FORMAT sections 1 and 9.4, HANDBUILT_WORLD 6.1.
  - world/ has only the terrain today, so the embedded world.bin is byte-identical to 4.1's.
- src/world/handworld.cpp/.h: loadHandWorld reads the roads when world.bin has them, else an empty network as before, and logs the counts. src/main.cpp gains one include, for roadsbin.cpp.
- build.sh: worldc's dependency list gains the files it now includes.
- src/world/roomlight.h (on a6fcf2b8): adds roomMinute(timeOfDay), which the night agent asked for, so the CB and the CPU callers share one integer.
- tests/world/worldmodel_test.cpp (on cec03b2b):
  - An exact round trip: every field, the ids, and the hash working after the read.
  - An empty network, and a network written without ids.
  - Six damaged sections, each refused with a reason and an empty network: truncated, one byte too many, another version, an edge naming node 1000, empty, and a world.bin without the section.
  - roomMinute.
