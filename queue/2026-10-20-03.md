# PC package 2026-10-20-03: the source-built updater, live

kind: run (a `build` of the ref first, then two starts of the game)
ref: 7b9146dffc92b67853291c38c699ae0978e5797d (P: snapshot 62, the head of PR #55; main merged it as 0bdeab3f4de31a6d5962b85b2779e84f6874bfb3)
args: `--width 1280 --height 720 --datadir="<worktree>\pcdata"`, no automated-run flag (the updater skips those)

Why: the updater builds main's source with the player's own compiler (README "Updates"). The cloud can't run it
end to end: it has no MSVC, and api.github.com rate-limits its shared address. This package does it on this PC, with
GitHub itself. A build of P sees main one merge commit ahead (M, "Merge pull request #<n>: ..."). It downloads M's
source, builds it with MSVC in the background, keeps it as `bin\NeonTide.exe.pending`, and on a restart swaps it in.
The new exe carries M.

Before you start:
- This takes 15 to 30 minutes, most of it MSVC building M while the game sits in its main menu. If the user is at
  the PC, ask first (rule 5).
- Check main: `git ls-remote origin refs/heads/main` must name a commit other than P, and `git log -1 --format=%s <it>`
  must start with "Merge pull request". Call it M.
  - If main is P itself (a fast-forward), stop and report `error: main is the ref`. There's nothing to update to.
  - If main moved past M, that's fine: the updater builds main's newest. Report the commit the log names.

Do, in PowerShell, in the worktree `..\neon-tide-pc-2026-10-20-03` (`git worktree add --detach` at the ref, rule 1):

1. Build P: `cmd /c .\build.bat`. Note the return code and the wall time. Check that the exe carries P (the updater
   compares it with main):
   ```powershell
   $P = (git rev-parse HEAD).Trim()
   [Text.Encoding]::ASCII.GetString([IO.File]::ReadAllBytes("$PWD\bin\NeonTide.exe")).Contains($P)   # must be True
   ```
2. Set up the data folder, windowed. settings.ini defaults to fullscreen; this file turns it off and keeps
   Automatic Updates on. The game reads it from the data folder:
   ```powershell
   $data = "$PWD\pcdata"; $res = "$PWD\pcresults"
   New-Item -ItemType Directory -Force $data, $res | Out-Null
   Set-Content -Encoding ascii "$data\settings.ini" "fullscreen=0`r`nauto_update=1"
   $args1 = "--width 1280 --height 720 --datadir=`"$data`""   # (no backslash before the closing quote: the game adds it)
   ```
3. First start: `$g = Start-Process "$PWD\bin\NeonTide.exe" -ArgumentList $args1 -PassThru`.
   - Within 30 s, `$data\log.txt` must say `Data dir: <worktree>\pcdata\` (rule 4); otherwise close the game and
     stop.
   - Wait, at most 45 minutes, until the log has one of these: `Updater: built `, `Updater: the update build failed`,
     `Updater: not built`, `Updater: no update`, `Updater: up to date`, `Unhandled`. Poll every 10 s:
     `Select-String -Path "$data\log.txt" -Pattern ...`.
   - Leave the window alone meanwhile. The build runs at below-normal priority in `$data\updates\<M>\`.
4. Once it says `built`, screenshot the window: the main menu's corner panel shows UPDATE READY, the pull request
   line, and RESTART NOW. Use PrintWindow with full content, which captures the window even when it is behind others.
   Otherwise use CopyFromScreen.
   ```powershell
   Add-Type -AssemblyName System.Drawing
   Add-Type @'
   using System; using System.Runtime.InteropServices;
   public static class W {
     [StructLayout(LayoutKind.Sequential)] public struct R { public int L, T, Rt, B; }
     [DllImport("user32.dll")] public static extern bool GetWindowRect(IntPtr h, out R r);
     [DllImport("user32.dll")] public static extern bool PrintWindow(IntPtr h, IntPtr dc, uint f);
   }
   '@
   function Shot($proc, $file) {
     $h = $proc.MainWindowHandle; $r = New-Object W+R; [W]::GetWindowRect($h, [ref]$r) | Out-Null
     $b = New-Object System.Drawing.Bitmap ($r.Rt - $r.L), ($r.B - $r.T); $gr = [System.Drawing.Graphics]::FromImage($b)
     $dc = $gr.GetHdc(); $ok = [W]::PrintWindow($h, $dc, 2); $gr.ReleaseHdc($dc)
     if (-not $ok) { $gr.CopyFromScreen($r.L, $r.T, 0, 0, $b.Size) }
     $b.Save($file, [System.Drawing.Imaging.ImageFormat]::Png)
   }
   Shot $g "$res\1_update_ready.png"
   ```
   (In Windows PowerShell 5.1, the here-string's closing `'@` must start its line: drop the indent when you paste.)
   Then keep the record before it goes. The install deletes it.
   ```powershell
   Copy-Item "$PWD\bin\NeonTide.exe.pending.json" "$res\pending.json"
   Get-FileHash "$PWD\bin\NeonTide.exe.pending" -Algorithm SHA256
   Copy-Item "$data\updates\*\build.log" "$res\build.log"
   ```
5. Restart:
   - First try the menu's "Restart now". It is the U key; the game reads the keyboard while its window has the focus:
     ```powershell
     $ws = New-Object -ComObject WScript.Shell
     if ($ws.AppActivate($g.Id)) { Start-Sleep 1; $ws.SendKeys('u') }
     ```
   - If `Updater: restarting into` is in the log within 20 s, the game quits on its own, installs the update and starts
     the new exe. The log goes on in the same file.
   - If not (focus is refused, or the key didn't land), close the game the normal way:
     `$g.CloseMainWindow(); $g.WaitForExit(120000)`. Copy `$data\log.txt` to `$res\log_1.txt`, because the next start
     overwrites it. Then start it again with the same `$args1`.
   - Either way, the first process installs (`Updater: installed`), starts the new exe and exits. Write down which way
     you went.
6. The new process (`Get-Process NeonTide`) opens its window. Wait, at most 2 minutes, for `Updater: up to date` or
   another `Updater: no update` line after `Updater: now running`. Then `Shot` it as `$res\2_after.png`: the corner
   shows "Version 0.02.7-dev", a dot, and M's first 7 digits, with no notice. Close it with `CloseMainWindow()` and copy
   the log to `$res\log_2.txt`.
7. Check the result:
   ```powershell
   $M = '<the commit the log names: "Updater: main is at <7 digits>", the full 40 from git ls-remote>'
   [Text.Encoding]::ASCII.GetString([IO.File]::ReadAllBytes("$PWD\bin\NeonTide.exe")).Contains($M)   # True
   (Get-FileHash "$PWD\bin\NeonTide.exe").Hash.ToLower()          # = pending.json's sha256
   Test-Path "$PWD\bin\NeonTide.exe.old", "$PWD\bin\NeonTide.exe.pending", "$PWD\bin\NeonTide.exe.pending.json"   # all False
   Get-ChildItem -Recurse -Name "$data\updates"                    # only <M>\build.log
   ```
8. Scrub every copied text file (rule 3): replace `$env:USERPROFILE` with `%USERPROFILE%`, and the user's name and the
   machine's name with `<user>` and `<pc>`. Then remove the worktree. It now holds untracked build output, so use
   `git worktree remove --force ..\neon-tide-pc-2026-10-20-03`.
