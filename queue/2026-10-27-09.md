# PC package 2026-10-27-09: the bundled compiler, on a real Windows PC

kind: run
ref: 062c9cd9701823176936e226882f337cf616c24e (main, PR #65: snapshot 72)

Why: the user asked for the updater's compiler to be inside the exe. Snapshot 72 adds `build.bat bundle` and the
updater's bundled compiler (README: The bundled compiler). It was tested under Wine only; this checks it on Windows.

Before you start:
- It takes about 15 minutes and downloads the pinned w64devkit release (61.5 MB, from github.com/skeeto/w64devkit),
  then unpacks about 340 MB, all inside the worktree. If the user is at the PC, ask first (rules 5 and 6).
- Keep everything inside the worktree: steps 1 and 4 point LOCALAPPDATA and the game's data folder there, so nothing
  is written to the user's own `%LOCALAPPDATA%\NeonTide`.

Do, in a worktree at the ref (rule 1), in one cmd window:
1. `mkdir pclocal pcdata`, then `set LOCALAPPDATA=<worktree>\pclocal` and `set NT_COMMIT=43001a9cd53d428484e663b8bac14ab673aff79e`
   (snapshot 71's merge, so that main is one merge ahead of the exe and the updater has an update to build).
2. `cmd /c .\build.bat bundle`. Report its return code, its time, and its last 15 lines: either "Built bin\NeonTide.exe"
   with no `NOTE:` line, or the `NOTE:` line that says why the compiler wasn't added. MSVC builds the game as usual.
3. `build\payload.exe show bin\NeonTide.exe --verify`, and report its output and the exe's size in bytes.
4. Write `pcdata\settings.ini` with `fullscreen=0` and `master_volume=0`, set `NEONTIDE_DATADIR=<worktree>\pcdata\`
   (rule 4), then run, with the paths unquoted (rule 4), and wait for it to exit (at most 20 minutes):
   ```
   bin\NeonTide.exe --update-test --update-bundled --datadir=<worktree>\pcdata\
   ```
   Report the return code (0: an update was built with the bundled compiler) and its wall time.
5. Run the same command again: this start installs the built update (return code 0). Then run
   `build\payload.exe show bin\NeonTide.exe --verify` again: the installed exe must still carry the compiler.

Report in results/2026-10-27-09/summary.md:
- each step's return code and time, the exe's size before and after;
- both `payload.exe show` outputs;
- every `Updater:` line of `pcdata\log.txt` (the compiler it picked, the unpack time, the build time, the install);
- every `Unhandled`, `FATAL`, `error`, `NOTE:` or `debug layer` line;
- whether any antivirus warning appeared (Windows Security notifications), and what it said.

Files: `pcdata\log.txt` and the update's `build.log` (under `pcdata\updates\`), both scrubbed (rule 3). Then remove the
worktree, with `pclocal` and `pcdata`.
